# SkillForge AI Roadmap

A learning-first roadmap. Finish a small, demonstrable milestone before adding the next layer.

## Milestone 1 — Browser-based MVP
- [x] Responsive single-page layout
- [x] Product brief form
- [x] Draft hooks, caption, voiceover, and 8-scene storyboard
- [x] Taglish, Filipino, and English modes
- [x] Copy individual outputs and the full draft
- [x] Sample input and content disclaimers
- [ ] Try it on both desktop and mobile
- [ ] Collect feedback and improve wording

## Milestone 2 — Learn core web development
- [ ] Change typography, spacing, or colors in `styles.css`
- [ ] Add a new field to the product brief
- [ ] Add a fourth tone and test all tones
- [ ] Understand `addEventListener`, arrays, and `map()` in `app.js`
- [ ] Record changes in Git commits with meaningful messages

## Milestone 3 — Creator workflow
- [ ] Add a manual checklist for verified product claims
- [ ] Add editable storyboard shots and duration
- [ ] Export the output as a text or Markdown file
- [ ] Save drafts locally only after explaining the privacy trade-offs
- [ ] Add templates for unboxing, demonstration, comparison, and problem/solution formats

## Milestone 4 — AI integration (later)
- [ ] Select an AI provider and review its pricing, terms, and data handling
- [ ] Create a small server-side API endpoint
- [ ] Store the API key in environment variables, never in browser code
- [ ] Validate inputs and bound output lengths
- [ ] Handle timeouts, rate limits, and provider errors
- [ ] Keep human review before publishing
- [ ] Add tests for prompt construction and response parsing

## Milestone 5 — BMS reporting prototype
- [ ] Use fictional/sample assets and readings only
- [ ] Create a structured shift handover form
- [ ] Format an observation, action taken, current status, and follow-up
- [ ] Include a clear “verify against site SOP” reminder
- [ ] Make no live controls or writes to real building systems
- [ ] Document limitations and safe human review

## Milestone 6 — Automation portfolio
- [ ] Map a workflow using a diagram
- [ ] Create a demo trigger → transform → review → output flow
- [ ] Connect a test form to a test spreadsheet with dummy data
- [ ] Document failure cases, privacy concerns, and how the workflow is tested
- [ ] Record a short walkthrough or add screenshots

## Definition of done for every feature
1. It solves one clear problem.
2. It works on a normal browser, or setup steps are documented.
3. Inputs and outputs are understandable.
4. Limitations and unsafe uses are documented.
5. A small manual test has been performed.
6. A clear commit explains what changed.
